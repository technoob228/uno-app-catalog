# Ворота установки (gate)

Приложения, у которых «админом становится тот, кто первым открыл адрес», у нас
так не работают. Схема compose-плана:

1. само приложение — БЕЗ `ports:` (снаружи до него не достучаться);
2. `init` (curlimages/curl) ждёт приложение по внутренней сети и создаёт
   админа через его API: логин — `UNO_OWNER_EMAIL` (email владельца аккаунта
   Uno) или фиксированный, пароль — `ADMIN_PASSWORD`, который сгенерировал
   control plane. Идемпотентно: если вход с этими данными уже проходит —
   ничего не делает (переустановка, повторный `compose up`);
3. `front` (socat — чистый TCP, заголовки прокси ноды доходят как есть)
   публикует порт ТОЛЬКО после `service_completed_successfully` у init.

`docker compose up -d` ждёт init, поэтому установка «Running» = админ создан.
Init упал → установка Failed, порт так и не открыт.

Логин и пароль владелец видит в карточке приложения в Uno Work
(`GET /api/v1/boxes/{id}/apps` → `credentials`).

Для приложений, где остальные люди регистрируются сами (Vaultwarden, Vikunja),
`front` — Caddy с пригласительной ссылкой: `/uno-invite/<INVITE_KEY>` ставит
cookie, без неё ручки регистрации отвечают 403.
